1. Informacion general

Que es VotaFacil?

VotaFacil es una aplicacion de escritorio para realizar votaciones electronicas de forma simple y segura. Permite a un administrador configurar candidatos y electores, abrir y cerrar procesos de votacion, y consultar resultados en tiempo real.

Los electores pueden iniciar sesion con su codigo y contrasena, elegir a su candidato preferido y emitir su voto de manera rapida e intuitiva.

Caracteristicas principales

Gestion de Candidatos

Crear, modificar, eliminar y consultar candidatos. Cada candidato tiene codigo, nombre, partido y descripcion.

Gestion de Electores

Administrar electores con cedula, nombre y contrasena. Se pueden habilitar o deshabilitar para el acceso.

Votacion Segura

Cada elector puede votar una sola vez. El voto es secreto y no se expone la identidad del votante.

Escrutinio en Tiempo Real

Ver resultados actualizados con conteo de votos, porcentajes y participacion total.

Busqueda Global

Buscar entre candidatos, electores y votos desde un solo lugar con coincidencia parcial.

Exportacion CSV

Exportar cualquier dato a archivos CSV para analisis externo o reportes.

2. Instalacion

Requisitos previos

RequisitoVersion minimaDonde obtenerlo
Java Development Kit (JDK)21Adoptium o Oracle
Apache Maven3.8+maven.apache.org
IDE (opcional)CualquieraNetBeans, IntelliJ IDEA, VS Code

Paso 1: Clonar el repositorio

Abre una terminal y ejecuta el siguiente comando para descargar el codigo fuente:

git clone https://github.com/tu-usuario/VotaFacil-NetBeans.git cd VotaFacil-NetBeans

Paso 2: Verificar la instalacion de Java

Asegurate de que Java 21 este instalado correctamente:

java -version javac -version

Debe mostrar algo como java version "21.x.x". Si no lo muestra, necesitas instalar el JDK.

Paso 3: Verificar la instalacion de Maven

Verifica que Maven este disponible:

mvn -version

Si el comando no es reconocido, agrega la carpeta bin de Maven a la variable de entorno PATH.

Paso 4: Compilar el proyecto

Maven descargara las dependencias automaticamente la primera vez que ejecutes este comando:

mvn compile

Si todo sale bien, veras un mensaje de BUILD SUCCESS.

Paso 5: Ejecutar la aplicacion

Para iniciar VotaFacil, ejecuta:

mvn javafx:run

Se abrira la ventana de la aplicacion con la pantalla de inicio de sesion.

Alternativa con NetBeans: Haz clic derecho en el proyecto y selecciona "Run" o presiona F6.

Estructura de archivos de datos

Al ejecutar la aplicacion, se crea automaticamente una carpeta datos/ en la raiz del proyecto con los siguientes archivos:

Los datos se guardan automaticamente al cerrar la aplicacion, al cerrar sesion y despues de cada voto emitido.

3. Arquitectura

Arquitectura por capas

VotaFacil esta organizado en 5 capas separadas por responsabilidad. Cada capa solo se comunica con la capa que tiene justo debajo, lo que hace el codigo mas facil de entender y mantener.

Interfaz Grafica (ui/)
↓
Logica de Negocio (service/)
↓
Capa de Persistencia (data/)
↓
Modelos de Datos (model/)
↓
Excepciones (exception/)

Que hace cada capa?

Interfaz Grafica (ui/)

Contiene todas las pantallas que ve el usuario. Cada pantalla es una clase JavaFX que construye la interfaz de forma programatica (sin archivos FXML). Las clases principales son:

  • LoginScene — Pantalla de inicio de sesion
  • MenuAdminScene — Panel principal del administrador con navegacion lateral
  • MenuElectorScene — Pantalla del elector con acceso a votar
  • CandidatosScene — CRUD de candidatos
  • ElectoresScene — CRUD de electores
  • VotacionScene — Pantalla donde el elector elige su candidato
  • EscrutinioScene — Resultados de la votacion
  • BusquedaScene — Busqueda global entre todas las entidades
  • ExportacionScene — Exportacion de datos a CSV

Tambien incluye Navegacion (cambia entre pantallas) y Dialogos (muestra alertas).

Logica de Negocio (service/)

ServicioVotacion es la clase central. Maneja toda la logica: autenticacion, creacion y edicion de candidatos y electores, apertura/cierre de votacion, emision de votos, conteo de resultados, busqueda y preparacion de datos para exportar.

Capa de Persistencia (data/)

Se encarga de guardar y cargar los datos en archivos de texto plano. DatosVotacion maneja los archivos de candidatos, electores y votos. CsvExporter genera archivos CSV con formato correcto.

Modelos de Datos (model/)

Son las clases que representan la informacion: Candidato, Elector, Voto, ResultadoEscrutinio y ResultadoBusqueda. Son objetos simples con campos y metodos basicos.

Excepciones (exception/)

Contiene 5 excepciones personalizadas que se lanzan cuando algo sale mal: candidato duplicado, elector duplicado, elector ya voto, votacion cerrada y exportacion fallida.

Flujo de ejecucion

Asi se ejecuta el programa paso a paso:

  1. Main.java inicia la JVM y llama a Application.launch()
  2. App.java configura la ventana, carga los datos desde archivos y muestra el login
  3. LoginScene pide usuario y contrasena al usuario
  4. ServicioVotacion.iniciarSesion() valida las credenciales
  5. Si es admin, se muestra MenuAdminScene. Si es elector, MenuElectorScene
  6. El usuario navega por las pantallas usando los botones
  7. Al cerrar sesion o cerrar la ventana, DatosVotacion.guardar() persiste todo en archivos

4. Modelos de datos

Los modelos son clases Java que representan la informacion que maneja el sistema. Cada modelo tiene campos que guardan los datos y metodos para acceder a ellos. Estan en el paquete model/.

Candidato

Representa a un candidato electoral. Tiene un codigo unico y un nombre unico que no se pueden repetir.

CampoTipoDescripcionEjemplo
codigoStringIdentificador unico del candidatoCAN001
nombreStringNombre completo (unico)Juan Perez
partidoStringNombre del partido politicoPartido Progreso
descripcionStringDescripcion del plan o propuestaEducacion gratuita...
Archivo: Se guarda en datos/candidatos.txt con el formato: codigo;nombre;partido;descripcion

Elector

Representa a un votante. Tiene contrasena para iniciar sesion y un indicador de si ya voto o no.

CampoTipoDescripcionEjemplo
codigoStringIdentificador unico del electorE001
cedulaStringCedula de identidad (unica)12345678
nombreStringNombre completoAna Lopez
contrasenaStringContrasena de acceso (texto plano)clave123
yaVotobooleanSi ya emitio su votofalse
habilitadobooleanSi puede iniciar sesion (solo en memoria)true
Nota: El campo habilitado no se guarda en archivos. Siempre se carga como true desde el archivo.

Metodos de utilidad:

  • getEstado() — Devuelve "Ya voto" o "Pendiente"
  • getHabilitadoTexto() — Devuelve "Si" o "No"
  • getContrasenaOculta() — Devuelve asteriscos (****) para ocultar la contrasena en la tabla

Voto

Representa un voto emitido. Conecta al elector con el candidato elegido, pero la identidad del votante nunca se muestra.

CampoTipoDescripcionEjemplo
codigoVotoStringIdentificador unico del votoV001
codigoElectorStringCodigo del elector que voto (secreto)E001
codigoCandidatoStringCodigo del candidato elegidoCAN001
Secreto del voto: El campo codigoElector nunca se muestra en ninguna pantalla ni en los archivos CSV exportados.

ResultadoEscrutinio

Es un objeto de tipo DTO (objeto de transferencia de datos) usado solo para mostrar resultados en la tabla de escrutinio. Es inmutable (no tiene metodos para cambiar sus valores).

CampoTipoDescripcionEjemplo
codigoStringCodigo del candidatoCAN001
nombreStringNombre del candidatoJuan Perez
partidoStringPartido politicoPartido Progreso
votosStringCantidad de votos recibidos15
porcentajeStringPorcentaje de votos37.5%

ResultadoBusqueda

Tambien es un DTO. Se usa para mostrar los resultados de la busqueda global en una tabla con el tipo de entidad y sus datos formateados.

CampoTipoDescripcionEjemplo
tipoStringTipo de entidad encontradaCandidato
datosStringDatos formateados de la entidadCAN001 | Juan Perez | Partido Progreso

Resumen de relaciones

Candidato — Tiene codigo, nombre, partido, descripcion
↑↑ relacionado por codigo
Voto — Conecta codigoElector con codigoCandidato
↑↑ relacionado por codigo
Elector — Tiene codigo, cedula, nombre, contrasena

5. Logica de negocio (ServicioVotacion)

ServicioVotacion es la clase mas importante del proyecto. Contiene toda la logica de negocio de la aplicacion. Todos sus metodos son estaticos (no se crea una instancia de la clase).

Esta clase se divide en varias categorias de funciones que se explican a continuacion.

Autenticacion

Estos metodos manejan el inicio y cierre de sesion de los usuarios.

MetodoQue haceQue devuelve
iniciarSesion(usuario, contrasena) Valida las credenciales del usuario "admin", "elector" o mensaje de error
cerrarSesion() Limpia la sesion del elector actual Nada (void)
getElectorActual() Obtiene el elector que esta logueado Objeto Elector o null
getElectorActualNombre() Obtiene el nombre del elector logueado String con el nombre

Como funciona iniciarSesion():

  1. Si el usuario es "admin" y la contrasena es "admin123", devuelve "admin"
  2. Si no, busca un elector con ese codigo
  3. Si lo encuentra, verifica la contrasena
  4. Si la contrasena es correcta, verifica que este habilitado
  5. Si no ha votado, verifica que la votacion este abierta
  6. Si todo esta bien, guarda el codigo del elector actual y devuelve "elector"

Gestion de Candidatos

MetodoQue haceLanza excepcion
registrarCandidato(codigo, nombre, partido, descripcion) Crea un candidato nuevo CandidatoDuplicadoException
modificarCandidato(codigo, nombre, partido, descripcion) Modifica un candidato existente CandidatoDuplicadoException
eliminarCandidato(codigo) Elimina un candidato Ninguna
buscarCandidatoPorCodigo(codigo) Busca un candidato por su codigo Ninguna
getCandidatos() Devuelve la lista completa de candidatos Ninguna
Restriccion: No se pueden agregar, modificar o eliminar candidatos mientras la votacion esta abierta.

Gestion de Electores

MetodoQue haceLanza excepcion

modificarElector(codigo, cedula, nombre, contrasena) Modifica un elector existente ElectorDuplicadoException
eliminarElector(codigo) Elimina un elector Ninguna
habilitarElector(codigo) Permite al elector iniciar sesion Ninguna
deshabilitarElector(codigo) Impide al elector iniciar sesion Ninguna
getElectores() Devuelve la lista completa de electores Ninguna

Control de Votacion

MetodoQue haceCondiciones
abrirVotacion() Abre el periodo de votacion Requiere minimo 2 candidatos y 1 elector
cerrarVotacion() Cierra el periodo de votacion Siempre funciona
isVotacionAbierta() Consultar si la votacion esta abierta Devuelve true o false
votar(codigoCandidato) El elector emite su voto La votacion debe estar abierta

Que pasa cuando un elector vota:

  1. Se verifica que la votacion este abierta
  2. Se marca al elector como "ya voto" (yaVoto = true)
  3. Se crea un objeto Voto y se agrega a la lista
  4. Se cierra la sesion del elector automaticamente

Escrutinio y Estadisticas

MetodoQue calcula
contarVotos(codigoCandidato) Cuantos votos recibio un candidato especifico
candidatosPorVotosDesc() Lista de candidatos ordenada de mayor a menor cantidad de votos
totalVotosEmitidos() Total de votos que se han emitido
totalElectoresHabilitados() Cantidad de electores que pueden votar
porcentajeVotos(votosCandidato) Que porcentaje representa un candidato del total
porcentajeParticipacion() Que porcentaje de electores ya voto

Formula de participacion:

Participacion = (Total de votos emitidos / Total de electores habilitados) x 100

Busqueda Global

MetodoQue hace
buscarGlobal(termino) Busca el termino en candidatos (codigo, nombre, partido, descripcion), electores (codigo, cedula, nombre) y votos (codigo de voto)

La busqueda es parcial y no distingue mayusculas/minusculas. Por ejemplo, buscar "juan" encontrara al candidato "Juan Perez".

Estos metodos preparan los datos en formato de arreglos de strings para que CsvExporter los escriba en archivos CSV:

6. Persistencia

Como se guardan los datos?

VotaFacil no usa base de datos. Los datos se guardan en archivos de texto plano dentro de una carpeta llamada datos/. Cada linea del archivo representa un registro, y los campos se separan con punto y coma (;).

DatosVotacion

Esta es la clase principal de persistencia. Mantiene tres listas en memoria y las lee/escribe desde archivos.

Listas en memoria

ListaTipoArchivo
candidatosList<Candidato>datos/candidatos.txt
electoresList<Elector>datos/electores.txt
votosList<Voto>datos/votos.txt

Metodos principales

MetodoQue hace
cargar() Crea la carpeta datos/ si no existe, luego lee los tres archivos y llena las listas en memoria
guardar() Escribe el contenido de las tres listas en sus archivos correspondientes
Cuando se guardan los datos automaticamente:
  • Cuando se cierra la aplicacion (clic en la X de la ventana)
  • Cuando el administrador cierra sesion
  • Cuando un elector emite su voto

Formato de los archivos

candidatos.txt

Cada linea contiene un candidato con sus 4 campos separados por punto y coma:

📄 datos/candidatos.txt
CAN001;Juan Perez;Partido Progreso;Educacion gratuita, salud y vivienda para todos CAN002;Maria Gonzalez;Partido Union;Seguridad ciudadana y empleo para la juventud CAN003;Carlos Rodriguez;Partido Democrata;Transparencia y lucha contra la corrupcion CAN004;Ana Martinez;Partido Fuerza;Apoyo a pequenos emprendedores y al comercio local

electores.txt

Cada linea contiene un elector con 5 campos. El ultimo campo indica si ya voto (true/false):

📄 datos/electores.txt
E001;12345678;Ana Lopez;clave123;false E002;23456789;Luisa Perez;clave456;false E003;34567890;Carlos Gomez;clave789;false E004;45678901;Marta Ruiz;claveabc;false E005;56789012;Jorge Diaz;clavedef;false

votos.txt

Cada linea contiene un voto con 3 campos: codigo del voto, codigo del elector y codigo del candidato:

📄 datos/votos.txt
(vacio - aun no se han emitido votos)

Como se lee y escribe un archivo

El proceso de lectura y escritura usa clases de Java estandar (BufferedReader y BufferedWriter).

Leer un archivo

  1. Se abre el archivo con BufferedReader
  2. Se lee linea por linea hasta llegar al final
  3. Cada linea se divide con split(";")
  4. Se crea un objeto (Candidato, Elector o Voto) con los campos obtenidos
  5. El objeto se agrega a la lista correspondiente

Escribir un archivo

  1. Se abre el archivo con BufferedWriter
  2. Se recorre la lista de objetos
  3. Cada objeto se convierte a una linea con los campos separados por punto y coma
  4. Se escribe cada linea en el archivo

CsvExporter

Esta clase se encarga de exportar datos a archivos CSV (Comma-Separated Values). Los archivos CSV se pueden abrir en Excel, Google Sheets u otras herramientas de analisis.

Metodos

MetodoQue hace
exportar(archivo, cabeceras, filas) Escribe un archivo CSV con cabeceras y datos
campoCSV(valor) Escapa un campo: si contiene comas, comillas o saltos de linea, lo encierra entre comillas dobles

Cabeceras predefinidas

ConstanteColumnas
CABECERAS_CANDIDATOS Codigo, Nombre, Partido, Descripcion
CABECERAS_ELECTORES Codigo, Cedula, Nombre, Estado
CABECERAS_ESCRUTINIO Codigo, Nombre, Partido, Votos, Porcentaje
Nota importante: La exportacion de electores muestra el "Estado" (Pendiente/Ya voto) pero no incluye la contrasena por seguridad. Tampoco se exporta la identidad del elector que voto en los resultados del escrutinio.

Manejo de errores

Si ocurre un error al leer o escribir archivos de datos (por ejemplo, permisos de escritura, disco lleno), el error se imprime en la consola pero no se detiene la aplicacion.

Si ocurre un error al exportar a CSV, se lanza una ExportacionFallidaException y se muestra un dialogo de error al usuario.

7. Interfaz grafica

La interfaz grafica esta construida con JavaFX. Cada pantalla es una clase Java que construye su layout de forma programatica (sin archivos FXML). Las pantallas se conectan entre si mediante botones que cambian la escena mostrada.

Pantalla de Inicio de Sesion

Clase: LoginScene.java  |  Tamanio: 460 x 420 px

Elementos visuales

  • Eslogan "La forma mas sencilla de votar"
  • Linea decorativa separadora
  • Campo "Usuario" (TextField)
  • Campo "Contrasena" (PasswordField)
  • Boton "Iniciar Sesion" con efecto hover

Comportamiento

  • Si las credenciales son de admin, va al MenuAdminScene

  • Si hay error, muestra un dialogo de error

Panel del Administrador

Usa un layout BorderPane con una barra de navegacion oscura a la izquierda y un area de contenido a la derecha.

8. Excepciones

Manejo de errores con excepciones

VotaFacil usa excepciones personalizadas para manejar errores de negocio. Son clases que extienden Exception (excepciones verificadas) y se lanzan cuando algo no esta permitido o hay un problema.

Cuando se lanza una excepcion, la capa de interfaz la captura y muestra un dialogo de error al usuario con el mensaje correspondiente.

CandidatoDuplicadoException

Cuando se lanza

Cuando se intenta registrar o modificar un candidato y:

  • El codigo ya existe en otro candidato (sin importar mayusculas/minusculas)
  • El nombre ya existe en otro candidato (sin importar mayusculas/minusculas)
  • El campo codigo o nombre esta vacio

Metodos que la lanzan

  • ServicioVotacion.registrarCandidato()
  • ServicioVotacion.modificarCandidato()
Ejemplo: Si ya existe "CAN001 - Juan Perez" e intentas crear otro candidato con nombre "juan perez", se lanza esta excepcion porque el nombre ya existe (ignorando mayusculas).

ElectorDuplicadoException

Cuando se lanza

Cuando se intenta registrar o modificar un elector y:

  • El codigo ya existe en otro elector
  • La cedula ya existe en otro elector
  • Los campos codigo, cedula o nombre estan vacios

Metodos que la lanzan

  • ServicioVotacion.registrarElector()
  • ServicioVotacion.modificarElector()

ElectorYaVotoException

Cuando se lanza

Cuando un elector que ya emitio su voto intenta iniciar sesion de nuevo. Esto garantiza que cada persona solo pueda votar una vez.

Metodo que la lanza

  • ServicioVotacion.iniciarSesion()
Importante: Una vez que un elector vota, no puede volver a ingresar al sistema hasta que un administrador reinicie el proceso de votacion.

VotacionCerradaException

Cuando se lanza

Cuando un elector intenta hacer alguna accion de votacion pero la votacion no esta abierta. Esto puede ocurrir en dos momentos:

  • Al intentar iniciar sesion cuando la votacion esta cerrada
  • Al intentar votar cuando la votacion se cerro

Metodos que la lanzan

  • ServicioVotacion.iniciarSesion()
  • ServicioVotacion.votar()

ExportacionFallidaException

Cuando se lanza

Cuando ocurre un error de entrada/salida al intentar escribir un archivo CSV. Puede pasar por:

  • Falta de permisos de escritura en la carpeta seleccionada
  • El disco esta lleno
  • El usuario cancelo el selector de archivos
  • Error inesperado de sistema de archivos

Metodo que la lanza

  • CsvExporter.exportar()

Resumen de todas las excepciones

ExcepcionCuando ocurreSe resuelve con
CandidatoDuplicadoException Codigo o nombre de candidato duplicado o vacio Corregir los datos e intentar de nuevo
ElectorDuplicadoException Codigo o cedula de elector duplicada o campos vacios Corregir los datos e intentar de nuevo
ElectorYaVotoException Un elector que ya voto intenta iniciar sesion El elector no puede hacer nada hasta reiniciar votacion
VotacionCerradaException Intentar votar o loguearse cuando la votacion esta cerrada El admin debe abrir la votacion primero
ExportacionFallidaException Error al escribir archivo CSV Verificar permisos de escritura e intentar de nuevo

Como se manejan en la interfaz

Todas las excepciones se capturan en los metodos de accion de los botones (por ejemplo, al hacer clic en "Agregar" o "Iniciar Sesion"). El patron es siempre el mismo:

try { ServicioVotacion.algunMetodo(...); Dialogos.informacion("Operacion exitosa"); } catch (MiExcepcion ex) { Dialogos.error(ex.getMessage()); }

El mensaje de la excepcion se muestra en un dialogo de error nativo de JavaFX con boton "OK".

9. Reglas de negocio

Estas son todas las reglas que el sistema respalda. Estan implementadas en la clase ServicioVotacion y se aplican automaticamente cuando el usuario realiza acciones.

1. Credenciales del administrador

Regla

El administrador tiene credenciales fijas que no se pueden cambiar desde la interfaz.

Valores

Usuario: admin
Contrasena: admin123

Nota de seguridad: Estas credenciales estan hardcodeadas en el codigo fuente. En un sistema de produccion se deberian guardar de forma segura (base de datos con hash de contrasena, variables de entorno, etc.).

2. Unicidad de candidatos

Un candidato se identifica por dos campos que deben ser unicos en todo el sistema:

  • Codigo — Unico, sin importar mayusculas/minusculas (ej: "can001" es igual a "CAN001")
  • Nombre — Unico, sin importar mayusculas/minusculas (ej: "juan perez" es igual a "Juan Perez")

Si se intenta crear un candidato con un codigo o nombre que ya existe, se lanza CandidatoDuplicadoException.

3. Unicidad de electores

Un elector se identifica por dos campos que deben ser unicos:

  • Codigo — Unico, sin importar mayusculas/minusculas
  • Cedula — Unica, exacta (distingue mayusculas/minusculas)

Si se intenta crear un elector con un codigo o cedula repetida, se lanza ElectorDuplicadoException.

4. Requisitos para abrir votacion

La votacion no se puede abrir si no se cumplen estas condiciones minimas:

RequisitoCantidad minima
Candidatos registrados2 o mas
Electores registrados1 o mas

Si no se cumplen, el metodo abrirVotacion() devuelve un mensaje de error explicando que falta.

Por que 2 candidatos minimo? Porque una votacion con solo un candidato no tiene sentido democratico.

5. Un voto por elector

Cada elector puede emitir exactamente un voto. Despues de votar:

  • Se marca al elector con yaVoto = true
  • Se cierra la sesion automaticamente
  • Si el elector intenta iniciar sesion de nuevo, recibe un error
Importante: No hay forma de anular un voto o cambiar el candidato elegido una vez emitido.

6. Secreto del voto

La identidad del elector que voto nunca se expone en:

  • La pantalla de escrutinio (solo muestra candidato, votos y porcentaje)
  • Los archivos CSV exportados
  • La busqueda global

El campo codigoElector existe en el objeto Voto internamente, pero no se muestra en ninguna interfaz.

7. Bloqueo durante la votacion

Mientras la votacion esta abierta, el administrador no puede:

  • Agregar nuevos candidatos
  • Modificar candidatos existentes
  • Eliminar candidatos

Los botones correspondientes se deshabilitan automaticamente en la interfaz. Esto garantiza que la lista de candidatos sea estable durante la votacion.

8. Proteccion de electores que ya votaron

Un elector que ya voto no puede ser modificado ni eliminado desde la interfaz de administracion.

Si el admin intenta modificarlo o eliminarlo, recibira un mensaje de error explicando que el elector ya emitio su voto.

9. Proteccion de candidatos con votos

Un candidato que tiene al menos un voto no puede ser eliminado.

Esto evita que se pierda la referencia de los votos emitidos.

10. Codigo de votos secuencial

Los codigos de voto se generan automaticamente en secuencia:

V001, V002, V003, V004, ...

El sistema busca el ultimo codigo usado y genera el siguiente incrementando en 1.

11. Persistencia automatica

Los datos se guardan automaticamente en los archivos de texto en tres momentos:

MomentoCuando ocurre
Cierre de aplicacionEl usuario hace clic en la X de la ventana
Cierre de sesionEl admin o elector hace clic en "Cerrar Sesion"
Despues de votarEl elector emite su voto

12. Habilitacion de electores

El campo habilitado de un elector funciona asi:

  • Cuando un elector nuevo se crea, esta habilitado por defecto
  • El admin puede habilitarlo o deshabilitarlo desde la interfaz
  • Un elector deshabilitado no puede iniciar sesion
  • Nota: El estado de habilitacion NO se guarda en archivos. Al reiniciar la aplicacion, todos los electores quedan habilitados
